## Scope

This ranks a limited set of options using a deterministic weighted scorer. Costs and on-time probabilities are modeled estimates and are labeled as such. Live layers (weather and others) are used where available; missing keys or unsupported legs stay estimated or are excluded with a reason. It is decision-support for disruption assessment, not a booking system or full network optimizer.

## Core contributions
- Deterministic multi-mode scoring engine + orchestrator
- Muse Spark / Wonder / SAM 3.1 / Muse Voice Transcribe integrations with deterministic fallbacks
- Meta Model API is the API platform used for accessing models. Muse Code is the coding agent used.
- Live snapshot + worldwide corridor support
- Route briefing, storm lab, and shareable incident brief UIs

# GridFork

Multi-agent reroute engine: live traffic, weather & disruption data across
sea, air, road and rail, scored by cost, time saved and on-time odds.

GridFork is a multi-agent cascade evaluation engine for multi-modal logistics
(sea, air, road, rail). A North Sea storm disrupts shipping into Rotterdam; four
specialist agents report per-mode findings, and an orchestrator ranks
quantified reroutes on Cost, Time Saved, On-Time Probability, and Confidence.

## How it works

- Deterministic core: the specialists and the ranking are pure Python, so
  the numbers are always reproducible. The baseline runs the engine over
  reference incident data; live snapshots run the same engine over
  measured conditions.
- Ask GridFork: the `/ask?q=` box tops every view and answers worldwide routes only, grounded solely in places you name
  (typed, dictated, picked in the lab, or the briefing's asked corridor), never a default location. Scenario
  and why-questions route to Muse Wonder, facts to Muse Spark, and every
  answer carries the deterministic fastest alternate across all four modes
  (paid per question, click only). Questions without places get free guidance
  instead of a guessed location. A hold-to-talk button beside it dictates the
  question via Muse Voice Transcribe; sending still needs the click.
- Muse Spark synthesis: the `/summary` endpoint attaches a narrative
  rationale generated by `muse-spark-1.3`, with a deterministic fallback
  when no key is set or the API is unreachable.
- SAM 3.1 visual verification: the `/vision` endpoint segments container
  reference imagery and blends the congestion score into the sea leg, with
  an `unavailable` fallback offline.
- Wonder what-if planner: the `/whatif?q=` endpoint turns an operator
  question into explicit assumptions (Muse Wonder live, deterministic
  parser offline) and the deterministic engine recomputes the ranking,
  returning before/after scores plus the assumptions.
- Ask-as-basis stages: `/summary`, `/whatif`, `/vision`, `/image`, and
  `/challenge` each accept `?corridor=` or `?from=&to=` and run against
  that asked corridor; Route Briefing adopts the latest ask as the basis
  of its collapsed AI analysis and evidence area.
- Phase 1 real data: the `/live` snapshot feeds measured North Sea wave
  height (Open-Meteo Marine, keyless) and Rotterdam wind into the sea leg
  through an explicit documented rule; costs and probabilities stay
  modeled estimates, and every field carries a provenance label.
- Phase 2 real data: the same snapshot adds air (OpenSky Network traffic,
  else keyless adsb.lol direct or via an `ADSB_BASE_URL` relay), road
  (TomTom flow ratios plus incident closures and a routed truck transit),
  rail (NS, DB, or keyless Entur disruption counts), and sea-leg vessel
  traffic (AISStream counts as measured context, never a delay input)
  through explicit documented rules. Each keyed layer needs its own free
  key;
  unconfigured keyed layers report `setup-required` and leave their
  values untouched.
- Worldwide snapshots: `GET /snapshot` ranks all four modes live for any
  corridor — six presets from the North Sea to the transpacific, or any
  two geocoded places. Same delay rules, agents, and scoring as the
  baseline; legs that cannot apply are excluded with a reason instead of
  a silent guess: open-ocean road/rail, rail with proven no-coverage,
  sea under 200 km. A failed rail lookup keeps an estimated leg rather
  than dropping it. The Storm Lab runs these on click, and its Ask box
  grounds in the selected corridor.

## Endpoints

- `GET /` — home: live attention panel (corridor, worst disruption, freshness), one primary briefing button, shortcuts to the other views
- `GET /health`
- `GET /demo/grid` — live grid: four labeled mode cards, ranked cards, live/baseline view, collapsible AI analysis and evidence
- `GET /demo/north-sea-storm` — findings plus ranked options (JSON)
- `GET /demo/north-sea-storm/summary` — plus Spark narrative rationale (`?corridor=` / `?from=&to=` for an asked corridor)
- `GET /demo/north-sea-storm/vision` — plus SAM ground truth (`?image_url=`, `?corridor=` / `?from=&to=`)
- `GET /demo/north-sea-storm/weather` — live wind or labeled fallback
- `GET /demo/north-sea-storm/live` — live snapshot: measured waves/wind drive the sea leg, Phase 2 air/road/rail layers join when keyed, per-field provenance included
- `GET /demo/north-sea-storm/ask?q=...` — one question about traffic, disruptions, and the ranking, grounded worldwide in the named places (typed, dictated, or `?corridor=` / `?from=&to=`). Routes scenario/why-questions to Wonder and facts to Spark (paid per question, setup-required offline) and always reports the deterministic fastest alternate across all four modes; questions without places get free guidance
- `GET /snapshot?corridor=<id>` (or `?from=<place>&to=<place>`) — live four-mode ranking for any corridor: legs, findings, ranked options, fastest alternate, per-field provenance
- `GET /demo/north-sea-storm/brief` — plus Muse Wonder decision explanation
- `GET /demo/north-sea-storm/image` — plus Muse Image illustration (`?corridor=` / `?from=&to=`)
- `GET /demo/north-sea-storm/openweights?model=` — Spark Open / Glimmer runner setup status (`spark-open`, `glimmer`)
- `GET /demo/north-sea-storm/whatif?q=` — Wonder assumptions plus before/after ranking for a what-if question (`?corridor=` / `?from=&to=`)
- `GET /demo/north-sea-storm/challenge?models=` — open-weight route challenge: both models critique three fixed cases, scored on agreement, schema validity, latency, and tokens (`?corridor=` / `?from=&to=`, `&mock=true` for canned critiques)
- `GET /demo/north-sea-storm/brief-card` — dated shareable brief: recommendation, impacts, alternatives, evidence sources, assumptions, estimate labels; print-friendly
- `GET /demo/storm-lab` — Scenario lab: worldwide snapshot runner (presets or custom places, Ask grounded in the corridor) plus a single-assumption what-if with observed/hypothetical before/after; free-form stages live in the route briefing
- `POST /demo/north-sea-storm/transcribe` — Muse Voice Transcribe for one base64 WAV clip (`{"audio_b64", "filename"}`)
- `GET /demo/routes` — route briefing: hero verdict with fastest-vs-best and win reasons, KPI strip, comparison cards, side brief, collapsible AI analysis and evidence (schematic plus stages)

## Infrastructure API

`POST /v1/cascade`  
Requires header `Authorization: Bearer <key>` and a JSON body with `from` and `to` fields (example: Rotterdam to Oslo).

Returns the same ranking schema as the demo (`ranked_options`, `findings`, `top_reasons`, `provenance`).

Disabled unless `GRIDFORK_API_KEY` is set in the environment.  
The public demo routes do not require this key.

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --port 8000
```

results, set `META_MODEL_API_KEY` in the environment first; without it every
endpoint still works on deterministic fallbacks. Tests run offline:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## Honest scope notes

- Costs, probabilities, and confidences are modeled estimates, labeled per field; legs are measured live where providers reach.
- Phase 2 keys (all free): OpenSky needs `OPENSKY_CLIENT_ID` plus
  `OPENSKY_CLIENT_SECRET` from an OAuth2 client at opensky-network.org
  (else keyless adsb.lol answers, optionally via an `ADSB_BASE_URL`
  relay on filtered networks);
  TomTom needs `TOMTOM_API_KEY` from developer.tomtom.com (no payment
  method; enable the Traffic and Routing products on the key); NS needs
  `NS_API_KEY` from apiportal.ns.nl (sent as the subscription-key
  header), or DB Timetables needs `DB_CLIENT_ID` plus `DB_API_KEY`
  from developer.deutschebahn.com — rail uses NS when set, else DB,
  else keyless Entur (nearest-station departures, no account). Without a key a
  keyed layer reports `setup-required` and makes no network call; keys
  stay in the environment, never in the repo.
- Vision uses reference imagery, not a live Rotterdam feed.
- The optional Meta Models grid section needs `META_MODEL_API_KEY` for
  the Wonder explanation (paid, on demand only) and a runner for open
  weights. Glimmer: install Ollama, run `ollama run muse-glimmer`
  (~17 GB download), set `GLIMMER_BASE_URL=http://localhost:11434/v1`.
  Spark Open needs a hosted provider: set `SPARK_OPEN_BASE_URL` to its
  OpenAI-compatible endpoint plus `SPARK_OPEN_API_KEY`, and
  `SPARK_OPEN_MODEL` if the provider's model slug differs (same
  `GLIMMER_MODEL_NAME` override exists). See `openweights_client.py`
  for the verified checkpoints, runners, and hardware notes. No weights
  are downloaded and no runner is started by this repo.
- The route challenge keeps the deterministic ranking authoritative:
  model critiques are labeled advisory and scored on agreement with the
  rank-1 pick, strict-schema validity, latency, and token usage.
- Hosted partner (checked Oct 31 2026): Fireworks serves Spark Open
  serverless at `https://api.fireworks.ai/inference/v1` as
  `accounts/fireworks/models/muse-spark-open` ($1.25/$4.25 per 1M tokens,
  US-only). Glimmer is NOT on Fireworks serverless (deprecated Sep 25
  2026 per their model page; on-demand deployments only). For a live
  Glimmer leg use Together AI serverless
  (`https://api.together.xyz/v1`, `meta-models/Muse-Glimmer-30B`,
  $0.35/$1.50 per 1M) or local Ollama. A full 6-call challenge costs
  a few cents.
- Open-model and voice prerequisites: no single partner is confirmed for
  both open models, so live comparison legs report `setup-required` /
  `unreachable` until runners are configured; `?mock=true` previews the
  panel with fixed canned critiques (labeled `mock`, no network).
  Voice transcription needs `META_MODEL_API_KEY` (`muse-voice-transcribe-1.0`,
  paid per audio hour); without it the endpoint reports `setup-required`.
  The microphone is used only while the talk button is held.
